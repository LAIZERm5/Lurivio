# Публикация на GitHub

Этот архив уже содержит содержимое корня будущего репозитория.
Сам репозиторий в вашем аккаунте **не создан и не опубликован**.

## 1. Подготовьте страницу

1. Создайте новый репозиторий **Lurivio** в своём аккаунте GitHub.
2. Description: **Capture URLs and QR codes from your screen. Local recognition for Windows.**
3. Visibility: Public, если хотите открыть код всем.
4. Не добавляйте другой README, LICENSE или .gitignore: они уже есть.
5. Рекомендуемые topics: `windows`, `ocr`, `qr-code`, `desktop-app`, `pyside6`, `clipboard`, `productivity`, `python`.

Код оформлен под MIT. До публикации убедитесь, что эта лицензия вам подходит.
Она не переопределяет лицензии сторонних библиотек и моделей.

## 2. Загрузите содержимое

Можно через GitHub Desktop или **Add file → Upload files**. Загрузите именно
содержимое папки Lurivio, чтобы **README.md лежал в корне**, а не ещё на один
уровень глубже. Не пропускайте `.github`, `.gitignore` и `.gitattributes`.
Не загружайте `.venv`, build, dist, ошибки/логи или настройки пользователя.

Если используете Git, откройте терминал в папке Lurivio:

```powershell
git init
git add .
git commit -m "Initial release: Lurivio 0.6.1"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/Lurivio.git
git push -u origin main
```

**YOUR_USERNAME замените на свой GitHub username.** Этот адрес — пример,
не уже существующий репозиторий. Авторизацию выполняйте через GitHub/Desktop/
credential manager; не записывайте токен в исходники или README.

## 3. Проверьте сборку

1. Откройте **Actions → Windows build**.
2. Дождитесь успешного завершения тестов и сборки.
3. Скачайте artifact **windows-portable**, извлеките вложенный Windows ZIP
   и проверьте программу на Windows.
4. Пройдите [чек-лист релиза](RELEASE_CHECKLIST_RU.md), включая QR-коды, запись сочетаний, глобальные кнопки мыши и один ЛКМ по трею. Проверьте горячую клавишу, смену комбинации и конфликт, Ctrl+V, уведомления,
   трей, автозапуск после выхода/входа, DPI 100/125/150/200% и второй монитор.

Если Actions запрещены политикой аккаунта/организации, сборка не запустится:
используйте Build_EXE.bat локально. Успех unit-тестов не подтверждает всю Win32-интеграцию.

## 4. Опубликуйте релиз

После реальной Windows-проверки:

```powershell
git tag v0.6.1
git push origin v0.6.1
```

Workflow повторно выполнит тесты/сборку и создаст **черновик предварительного релиза**
с `Lurivio-Windows.zip` и `SHA256SUMS.txt`. Откройте Releases, проверьте вложения
и вручную нажмите Publish release, сохранив пометку prerelease для этой бета-версии. Публикация использует штатный `GITHUB_TOKEN` в Actions;
не надо добавлять личный токен в код. Workflow выдаёт право записи содержимого
только job публикации. Политика организации может ограничить эти права.

Если уже существует черновик этого релиза, вложения обновляются. Опубликованный релиз workflow не перезаписывает. Не переиспользуйте тег для
новой версии: обновите VERSION/код/CHANGELOG и создайте новый тег.

## 5. Финальные штрихи страницы

- В About оставьте короткое описание и topics.
- Оставьте Releases видимыми в боковой панели.
- В Settings → Security включите Private vulnerability reporting, если доступно.
- При желании используйте `docs/assets/social-preview.png` как Social preview
  в Settings → General. Это отдельная обложка, не доказательство готовности бинарника.
- Не ставьте бейдж «CI passing» до первого успешного запуска Actions.
- После проверки обновите раздел «Статус» в README конкретными ОС/сценариями,
  не общим обещанием «работает везде».

README RU/EN, скриншоты, issue-формы, PR-шаблон, инструкции, changelog и лицензия
уже включены. В архиве нет готового Windows EXE — он появится после сборки.
